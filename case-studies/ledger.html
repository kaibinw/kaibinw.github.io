A full-stack, real-time budgeting app for two people and one household, in daily use within a week.

SLATE PROBLEM BUILD PROOF NEXT

Problem

Two people, one household, two credit cards, and a month-end of pasting PocketSmith into a spreadsheet. We couldn't see which card paid, or who was owed. Paid apps missed shared real-time entry, household budgets, and per-category alerts.

Constraints set before building

Two users, one householdAll data belongs to the household; a partner's entries appear instantly.
Real-time syncBoth people see the same numbers without refreshing. That's the whole point.
No bank syncManual entry only. No bank login is stored. Row-level security on every table limits a household to its own rows.
Mobile-first PWABoth users live on phones; the app installs to the home screen.
Free to runVercel and Supabase free tiers cover two users indefinitely.

What I built

Twelve sessions. I had scripted pipeline tools, not a full-stack app. I described what the household needed, then reviewed, tested, and steered.

Sessions 0–2Design references, the data model, and docs before code. Then 7 tables with row-level security on every table, and realtime: login, dashboard, entry, and live sync the same day.
Sessions 3–6PWA, drill-down, alerts, custom categories, CSV export, and a hand-rolled SVG donut. Dark mode, per-card tracking, 27 seeded bills, and keyword matching. The second person onboarded in session 4.
Sessions 7–12People and payback tracking, a two-page PDF, monthly close with locked months, and mobile polish. Then a design session for consent-based budget adjustments: live in production, off by default (opt-in in Settings).

Hours per session, not weeks. In production since 2026-05-13, with two daily users.

The dark mode story

Dark mode wasn't in the spec: a token system plus a Python migration removed every hardcoded hex, so the theme switches with one attribute.

Design is part of the stack

Visually heavy pages were mocked up in Claude Design, then handed to the coding session as the spec.

What it looks like, feature by feature

Same layout as the app. Merchants, people, and amounts below are invented sample data.

What it shows

  • The constraints ruled out off-the-shelf apps and picked the stack before any code.
  • Two people use it every day in place of the spreadsheet.
  • Payback tracking, bill suggestions, and dark mode came from watching real use.
