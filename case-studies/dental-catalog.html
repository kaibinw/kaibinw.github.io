Dental Catalog

SC FILESTK 02FPS 24IN 00:00:00:00 OUT 02:07:19:03
ROLE Product, design, engineering direction STACK Single HTML file · File System Access API STATUS v2

One HTML file for organising a local folder of dental imaging sets: tags, filters and a wipe compare. Sample data only. Designed to run locally.

SLATE PROBLEM BUILD PROOF NEXT

Problem

A folder of images, and no way to catalogue it, tag a set, or wipe between two versions. Paid catalog apps upload the files and charge a subscription.

Constraints set before building

One fileA single HTML file. It runs in the browser from the drive it sits on.
User-granted folderThe File System Access API reads only the folder the user picks. Designed to run locally; those files stay on the drive.
Tags stay localLabels are written beside the files. There is no account and no backend.

What I built

The page lists the granted folders as a grid and filters them by tag. A wipe compares two images in the set. A Sort Wizard samples pixel luminance with the Canvas API, suggests a label, batch-accepts the confident matches, and asks on the rest.

What it shows

  • Cataloguing, tagging, and filtering run in one HTML file.
  • The page reads a user-granted folder. It is designed to run locally, and the files stay on the drive.
  • The Sort Wizard suggests labels locally and asks when it is not confident.
