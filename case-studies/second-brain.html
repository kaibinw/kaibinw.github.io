Second Brain

A markdown vault with hard conventions, operated by agents: context stated once, for humans and machines alike.

SLATE PROBLEM BUILD PROOF NEXT

Problem

Answers lived in my head, old chats, and notes that went stale. Every agent session started cold. I wanted one vault a person or an agent can read, that stays current because using it files the gaps.

What I built

The wiki is the truthA page for every entity, project, and concept, listed in one index. If it isn't indexed, it isn't filed.
Hard rulesSources stay immutable. Pages are archived, never deleted. Every write updates the index and appends to the log.
Ingest, don't dumpA dev log, a URL, or a day's notes is discussed first, then filed, indexed, and logged.
Status vocabularyEach page is stub, developing, mature, or superseded, so staleness is visible.
Verify, don't guessBefore acting, a small read-only check tags the result confirmed or inferred.

Agents as the operating staff

A tiered protocol sets who may do what: strategy never writes code, consultants advise into a shared log, and execution gets a narrow brief. Each project folder has a charter the agent reads at session start.

The loop that makes it hold

  • Constitution. Every session reads it first.
  • Memory. The wiki and its logs.
  • Navigation. An index that points at the right page.
  • Verification. Check an assumption before acting on it.
  • Ratchet. Every session ends with a handoff.

It compounds

Every probe that misses becomes a page, so the vault gets more useful the more you ask it.

What it shows

  • A session starts warm: constraints and history are one read away.
  • Never-delete, always-log, and discuss-before-filing are rules, not habits.
  • Checking an assumption before building is why a guess never ships as a fact.
